ポンコツPdMの開発メモ ／ 教材用サンプル

Springフォーム・入力検証を、
テストを動かして確かめる

ブログの実装例を追試するための、独立した4つのMavenプロジェクトです。入力の形式、画面への再表示、Serviceの判断、Securityによる拒否を分けて確認します。実在の顧客・社内コード・データは含みません。

最初からすべて読む必要はありません。対象の記事に対応するフォルダーを選び、まずテストを通し、入力値や期待値を一つ変えて挙動を確かめてください。4つを1つのアプリとして起動する構成ではありません。

必要なもの・実行方法

  • JDK 17、Maven 3.9系。確認環境はJava 17.0.8／Maven 3.9.16。
  • Spring Boot 3.5.16の依存管理、Hibernate Validator 8.0.1.Finalを使用。最新版への追随を約束する教材ではなく、記事の結果を再現するために固定しています。
  • 初回はMaven Central等から依存関係を取得できるネットワークが必要です。外部DB、WordPressのアカウント、APIキーは不要です。

解凍したフォルダーから、対象のプロジェクトへ移動して実行します。

cd 01-validation-basics
mvn test

結果は各フォルダーの target/surefire-reports/ に作られます。依存関係を取得済みなら mvn -o test でオフライン実行できます。Javaの版やネットワークの失敗と、テストの期待値不一致を分けて確認してください。

おすすめの試し方

  1. src/test/java/ のテストを開き、送信値と期待結果を読む。
  2. 変更前の mvn test が成功することを確認する。
  3. 例として正常な数値を文字列に変える、必要な入力を除くなど、一条件だけ変える。
  4. HTTP応答だけでなく、項目エラー、再表示HTML、Serviceや保存処理の呼出有無を確認する。
  5. 何が保証でき、何を別のテストで確認する必要があるかを短く説明する。

この教材で検証していないこと

MockMvcとJUnitを中心にした検証です。実ブラウザーの操作、JavaScript、実ネットワーク経由の通信、外部DB・本番データ、同時実行の競合、負荷、アプリ全体のセキュリティ監査は対象外です。特にServiceの重複チェック例は、mockのRepositoryへの保存処理の呼出を確認するもので、本番DBへの永続化、競合や一意制約まで保証しません。

4番の認証済みリクエストは、テスト用の user() で利用者と権限を用意しています。実際のログイン処理やパスワード照合は検証していません。

3番のサンプルはテスト結果のHTMLを target/evidence/ に出力します。元の記事制作時の出力先から、この教材フォルダーの内側へ変更しています。アプリ本体の処理は変えていません。テスト専用のMockito設定は、この教材で必要なモックに絞ったもので、あらゆるfinalクラス等のモックを保証する設定ではありません。

安全な利用のために

教材のコードをそのまま本番の認証・データ保存の完成形として利用しないでください。ローカルでテストを実行する前提で、サーバーを外部公開する手順は含めていません。認証情報や社内データをサンプルへ書き込んで公開しないでください。

SHA256SUMS.txt には配布時のファイルのハッシュ値があります。依存ライブラリのバイナリ、実行済みのtargetフォルダー、社内資料は同梱していません。
